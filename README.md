# 保衛羊村自動化工具

這個專案用 Python 操作《保衛羊村》，目前維護敲狼挖礦、競技場和好友挑戰三個工具。程式會依設定的座標點擊，部分步驟使用圖片辨識判斷畫面。

設定步驟請看 [詳細操作與使用手冊 (USAGE.md)](./USAGE.md)。

## 安裝與啟動

執行環境為 Windows，使用 64 位元 Python。套件需求列在 `requirements.txt`。

在專案資料夾安裝套件：

```powershell
python -m pip install -r requirements.txt
```

安裝後，雙擊對應的批次檔：

| 工具 | 啟動檔 | 用途 |
| --- | --- | --- |
| 敲狼與挖礦 | `start_wolf_mine.bat` | 巡邏好友、點擊草地熱點、挖礦加速 |
| 競技場挑戰 | `start_arena_challenge.bat` | 執行防守、進攻或兩者的排程，處理戰鬥結算與抽獎 |
| 好友挑戰 | `start_friend_challenge.bat` | 依好友編號挑戰狼或防線 |

也可以在終端機執行，例如：

```powershell
python friend_challenge.py
```

`boss_auto_clicker.py` 和 `upgrade_and_attack.py` 已停止維護，檔案與原有啟動批次檔仍保留。

## 敲狼與挖礦

先框選草地，設定網格欄數與列數，再用第 1、6 位好友的位置生成好友列座標。程式會依序進入好友家園，執行勾選的敲狼與挖礦工作。

- 挖礦達到每日上限時，辨識並處理上限彈窗，取消勾選「挖礦加速」。
- 偵測到邀請好友彈窗時，關閉彈窗並停止巡邏。
- 執行中可用方向鍵切換好友或跳過目前步驟。
- 「標記預覽」可檢查位置，並拖曳標記微調座標。

## 競技場挑戰

支援防守、進攻、先攻後防、先防後攻四種模式，防守與進攻次數分開設定。進攻可以使用自動隊列，也可以指定出戰狼隻。

戰鬥後辨識結算畫面，依序點擊卡片、等待洗牌、翻牌及確認獎勵。不同步驟的等待時間可在「時間與辨識」調整。

## 好友挑戰

分別填入要挑戰狼、挑戰防線的好友編號，再選擇執行順序：

- 僅挑戰狼、僅挑戰防線。
- 先狼後防、先防後狼。
- 依編號混合：將兩份清單按好友編號由小到大執行。

開始前，請先把遊戲好友列切回第 1 頁，顯示第 1～6 位好友。程式依編號換頁；防線挑戰回家撤防後，保留原本的頁數紀錄。

按右方向鍵或「跳過」會中斷當前任務，繼續下一個任務；跳過不執行回家與撤防。

## 介面與設定

三個工具都把操作按鈕與日誌固定在上方，下方分成「任務設定」「座標設定」「時間與辨識」。座標欄位逐項排列；內容超出可視高度時才顯示捲軸。

關閉程式時會記住視窗位置、大小與最大化狀態。下次開啟時恢復；若原位置已不在目前的螢幕範圍，會移回可見區域。

敲狼和競技場的「以管理員執行」在視窗頂部。若操作正常，不必提升權限；遊戲以管理員權限執行、助手卻無法操作時，再將助手以相同權限執行。

| 檔案 | 內容 |
| --- | --- |
| `config.json` | 敲狼挖礦的座標、參數與視窗位置 |
| `arena_config.json` | 競技場的座標、參數與視窗位置 |
| `friend_challenge_config.json` | 好友編號、挑戰座標、參數與視窗位置 |
| `images/custom/` | 自行擷取的辨識圖片，已列入 Git 忽略清單 |

三個程式都在啟動時使用 per-monitor DPI 模式，讓介面保持清晰。好友挑戰首次讀取舊設定時，會依各螢幕的座標範圍轉換舊點位，並保留 `friend_challenge_config.json.before-dpi.bak` 備份；之後不會重複轉換。更新程式後需完全關閉再重開，才會套用。遊戲視窗位置、縮放比例或版面變動後，請用「座標設定」的標記預覽檢查點位。

## 共用程式與測試

- `modern_ui.py`：共用介面、座標列表、捲軸與日誌格式。
- `window_state.py`：敲狼與競技場的視窗位置記憶。
- `dpi_setup.py`：在介面與滑鼠套件載入前設定 DPI 模式。

執行回歸測試：

```powershell
python -m unittest dpi_setup_test ui_layout_test window_state_test wolf_mine_test friend_challenge_test friend_coordinates_test
```

測試涵蓋 DPI 模式、版面、視窗記憶與導覽流程。測試通過不代表每種遊戲畫面都能辨識；初次設定後，請先觀察少量任務的執行結果。
